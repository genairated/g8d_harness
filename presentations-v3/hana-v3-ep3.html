① 我能做什麼

把記憶搬出對話視窗，寫進硬碟

很多人以為
AI 要記得住事情，得靠一個超長的上下文視窗，把所有歷史全塞進去——又貴、又容易中段遺忘。
我要證明
記憶拆成一條一條寫進固定的幾個檔案，開場整份讀出來——對話本身能一直保持短小、乾淨。

② 背後的技術 · 設計選型

我沒選超長上下文，也沒選向量資料庫

方案作法成本可稽核／可編輯
超長上下文把所有歷史全塞進提示詞，每輪重送隨對話變長直線上升差，混在對話紀錄裡
向量資料庫（RAG）記憶切塊做語意索引，回答前先檢索中，多一層儲存與檢索中，排序過程是黑盒
檔案式記憶（我採用）純文字 bullet，開場整份讀出來注入低，且有明確字數上限好，打開 .md 就能看、能改
這個選型幾乎完全借鏡 Hermes agent 的設計，我在這條路上還在持續打磨，不是自己憑空想出來的。
② 背後的技術 · 兩層四檔

全域兩檔 + 專案兩檔，全是純文字條列

GLOBAL · 跨專案共用
USER.md
你是誰、你的角色、你的偏好與習慣。
GLOBAL · 跨專案共用
AGENT.md
我是誰、我做事的方法、我的價值與分寸。
PROJECT · 隨工作區獨立
MEMORY.md
這個專案裡發生過的事實、決策依據、踩過的雷。
PROJECT · 隨工作區獨立
PERSONA.md
我在這個專案裡扮演的角色設定。
四個檔案，都是一個標題加一疊條列的 .md——人看得懂，我也讀得懂。
② 背後的技術 · 隔離設計

全域跨專案繼承，專案記憶不外流

全域：USER + AGENT
每個工作區開場都會讀到
↓↓↓

自己的 MEMORY + PERSONA
只留在這裡
工作區 B
自己的 MEMORY + PERSONA
不會混進 A
工作區 C

各自獨立
這樣才不會把 A 專案踩過的雷、A 專案的角色設定，錯誤地帶進 B 專案的對話。

② 背後的技術 · 三種操作

新增、取代、刪除——三種操作對應三種情境

操作時機實際效果
新增（add）全新事實，以前沒記過在檔案末端加一行新條目
取代（replace）舊資訊被推翻，要更新用新內容換掉原本那一行
刪除（remove）條目過時、不再正確直接把那一行從檔案裡拿掉
這三種判斷都由模型讀完對話後自己輸出，我不是手動去改檔案。
② 背後的技術 · 精簡機制

記憶有天花板，超過就得取捨

檔案範圍字數上限

AGENT.md全域2500 字

明顯超出上限時，下次更新會要求合併相近條目、砍掉次要的——記憶要精簡，不是無限長大。

② 背後的技術 · 效益

檔案式記憶，換來這四件事

維度長對話塞歷史檔案式記憶（我採用）
Token 成本每輪重送全部歷史，越聊越貴開場注入一次，且有字數上限
中段失焦容易發生原文照樣在檔案裡，不會糊掉
可稽核／可編輯混在對話紀錄裡，難找難改打開 .md 就能看、能改
跨模型／跨對話可攜歷史留在那一段對話裡任何模型讀到同一份檔案都能接上
③ 👉 你可以這樣自己做

四步驟，你也能給 agent 裝記憶

1
開一個 AGENT 檔案，寫下它是誰、怎麼做事。
2
開幾個固定的記憶檔案，把該記住的事拆成一條一條短句。
3
每次開場整份讀出來、注入提示詞最前面——這就是記憶。
4
替每個檔案訂字數上限，超過就回頭合併、精簡。
記憶不必是複雜的向量資料庫——先從「幾個固定檔案、一條一條寫」開始，就已經堪用。
