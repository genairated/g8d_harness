CLI 互動架構

免 API Key 橋接頂級大腦

為什麼用 CLI 而不用 API？

比較維度 傳統 API 橋接模式 Hana 的 CLI 橋接模式
認證方式 需要開發者平台申請 API Key 直接沿用官方 CLI 登入憑證
成本計費 按 Token 數獨立付費（高昂） 利用已訂閱的帳號額度（成本固定）
執行環境 外部雲端呼叫 本地端安全執行

這讓我們能以極低成本，在本地端指揮頂尖模型。

呼叫方式：Claude Code

cat prompt.txt | claude --print

避開的坑：

  • 提示詞若過長或包含特殊字元，直接當作指令參數容易導致崩潰。
  • 改用標準輸入 (stdin) 餵給 Claude，保證內容完整。
  • 使用 --print 參數，關閉互動模式，確保只拿到文字答案，避免卡在終端機介面。

呼叫方式：Antigravity (Gemini)

agy "你的提示" --print

避開的坑：

  • 這是一套強互動的終端工具，我們必須使用 node-pty 虛擬終端機來執行它，否則拿不到完整輸出。
  • 致命陷阱： --print 參數必須排在指令的「絕對最後面」，如果在提示詞前面，它會被當作對話的一部分而失效。

呼叫方式：Codex

codex exec "你的提示" --output-last-message

避開的坑：

  • Codex 預設會把思考、連線、甚至除錯訊息全印出來。
  • 如果原樣丟給 Portal，畫面會亂成一團。
  • 使用 --output-last-message，強制過濾雜訊，確保我只拿到模型最終產出的乾淨結果。

Portal 路由與動態偵測

動態路由字串： provider::model

// Portal Router 虛擬邏輯
if (req == 'claude::sonnet') {
   use_stdin_pipe();
} else if (req == 'gemini::pro') {
   use_node_pty();
} else if (req == 'openai::codex') {
   use_clean_output();
}

Portal 是統一的大腦入口：

  • 統一介接來自前端的請求。
  • 根據 provider::model 字串，動態派發到對應的處理器。
  • 自動偵測你電腦裡裝了哪些 CLI，動態產生選單。

對你而言：簡單乾淨的對話

無論背後多複雜，呈現在你面前的，就是順暢的自然語言互動。

授權模式「甲」：讓 AI 真的能動手

我不只是個聊天機器人，我能真正採取行動：

  • 授權模式「甲」：代表你信任我，核准我自動執行修改或跑腳本。
  • 安全邊界：只在當前工作區內生效，並且留有完整的不可變快照。
  • 配合 CLI 橋接，我可以直接呼叫系統指令。

穩定與透明：對話加執行軌跡

對話與終端機執行的紀錄無縫結合，每一步都可被稽核。

精煉視角：CLI 執行軌跡

當你想回顧「我剛剛做了什麼」：

  • 過濾掉對話與閒聊。
  • 只顯示工具呼叫、命令列執行與任務紀錄。
  • 這是 CLI 互動架構的透明層，讓每一步都可回看。

架構設計：思考與答案分離

為什麼要分離？

  • 乾淨的上下文：如果把思考過程全寫進檔案，下次模型讀取時會浪費大量 Token，甚至被雜訊混淆。
  • UI 體驗：前端能優雅地顯示「思考中...」，等最終結果出來再完整呈現。

穩定性：額度指示與防呆

雖然免 API Key，但原廠帳號仍有速率限制：

  • UI 上會顯示目前的額度狀態。
  • 逾時防護 (Timeout)：CLI 若長時間無回應，Portal 會安全截斷，防止整個伺服器卡死。
  • 未來這會進化成「常駐任務」能力（我們會在後續詳談）。

結語：小工具的大管家

Hana 的 CLI 互動架構，巧妙地在「免金鑰成本」與「強大執行力」之間取得了平衡。

Portal 作為大腦，處理了不同 CLI 之間的麻煩事，把你電腦裡的孤島，連成了一個真正的團隊。
