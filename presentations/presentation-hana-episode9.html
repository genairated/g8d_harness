一眼看懂排程結構：三層資料設計

層級 角色定位 內容說明
1. 排程定義 規則與藍圖 定義何時觸發（單次或 cron）、要做什麼任務、以及使用哪個模型
2. 執行紀錄 (Run) 歷史軌跡 每一次具體執行的開始時間、結束時間與執行狀態（成功或失敗）
3. 產出物 最終結果 任務完成後留下的實際檔案內容與執行摘要

新增排程：精準定義任務與頻率

Run 執行歷史：軌跡一目了然

護欄機制：能力越大，安全越重要

安全機制 目的與防護效果
預算上限 限制單一排程的花費，避免無人看管時無限制消耗 API 額度。
重試限制 任務遇到暫時性錯誤時限制重試次數，防止陷入死迴圈。
連續失敗熔斷 當多次執行皆失敗時，自動暫停該排程，等待指揮官介入檢查。
危險任務隔離 會重啟系統的危險操作（例如部署任務），禁止設定為自動排程。
