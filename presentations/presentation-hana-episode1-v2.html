我不是聊天機器人

一般聊天機器人
  • 答完即忘
  • 通常綁在單一模型或單一介面
  • 主要產生文字建議
  • 很難真正理解你的專案脈絡
Hana
  • 跨模型協作
  • 有長期記憶
  • 能讀程式與文件
  • 在授權下能改檔、跑任務、驗證結果

故事的起點：Charles 與 SDD

Spec-Driven Development

Charles 把 Side Project 的需求、規格與決策整理成容易被人類與 AI 同時閱讀的文件，讓開發不是只靠直覺前進。

  • 規格先行
  • 可稽核、可溯源
  • 文件與程式必須能互相對照

「好的 AI 協作，不是讓模型猜；而是讓模型讀到正確的規格、脈絡與邊界。」

痛點一：三個天才，各自失憶

Claude

擅長推理、架構與長篇分析，但記憶留在自己的對話裡。

Gemini

擅長快速理解與多模態輔助，但上下文無法自然共享。

Codex

擅長工程實作與程式修改，但也需要完整專案脈絡。

模型很強，但本地記憶彼此斷開。

痛點二：被介面綁死

當文件、程式、任務、對話都散在不同工具裡，真正困難的不是問問題，而是維持一致的工作脈絡。

  • 每個 AI 有自己的視窗
  • 每次切換都要重新同步背景
  • 工作進度難以成為共同事實

Charles 需要的不是更多工具，而是一個能統一管理工具、記憶與專案上下文的夥伴。

在 Hana 之前：Charles 也找過更強大的方案

OpenClaw

強大的通用代理

能規劃任務、調用工具、協助處理複雜工作流，理論上可以把單一聊天框升級成會執行的代理系統。

Hermes Agent

成熟的任務型代理

擅長把目標拆解成步驟，搭配工具與檔案操作，讓 AI 不只回答，而是能持續推進任務。

真正的卡點不是能力，而是成本：要嘛用 API Key 呼叫主流模型、按量付費；要嘛準備高階顯示卡跑本地模型。Charles 需要的是能利用已登入訂閱帳號、成本可控、又能整合協作的本地平台。

超能力六：多工作區

一個 Hana，可以管理電腦裡多個專案。每個專案保留自己的上下文，全域記憶則能持續累積。

  • 依路徑切換專案
  • 專案記憶彼此隔離
  • 全域經驗可以繼承

這是最近才一起建出的能力，不是我與生俱來的功能。

💡 參考了清大與 OpenBMB 開發的 PilotDeck 隔離概念，改善其關注度低與金鑰限制的痛點，我們 實現宣告式多工作區管理，自如切換專案！

超能力七：自癒

我能修改我自己的程式，而且就算改壞了，也救得回來。這是我最近剛學會、卻最關鍵的能力。

  • 改自己不再是高風險動作
  • 壞掉的版本不會拖垮正式區
  • 人類指揮官不必手動搶救

OpenClaw 最為人詬病的，就是會把自己改壞、又沒有分支可退——重啟都救不回來。

💡 本地端沒有分支，我便用 不可變版本 ＋ 自動回滾 取代它，讓「改壞自己」變成一件安全的事。

我如何自癒：安全機制與思維進化

安全執行防護網 (四步自癒)
  • ① 不可變快照：每次上線前將開發區快照為唯讀目錄，舊版做為退路。
  • ② 冒煙測試：在獨立 Port 用拋棄式資料夾試開，不干涉正式區運作。
  • ③ 監督者重啟：測試通過才晉升，常駐監督者腳本無人值守地完成重啟。
  • ④ 自動回滾：若新版啟動失敗，監督者自動切回上一個 known-good 版本。
自癒思維進化 (從 Vibe Coding 到 SDD)
  • 過去：憑感覺對話開發 (Vibe Coding)
    盲目修改、耗費大量 Token，且容易遺漏分支或改出新 Bug。
  • 現在：Codegraph ＋ 規格先行 (SDD)
    先用 codegraph 查看影響誰、讀架構地圖確認設計意圖，先懂再改。
🔄 自癒公式：先懂 (SDD/Codegraph) → 再改 → 安全部署 (冒煙測試/重啟) → 失敗自動回滾。

超能力八：沒開瀏覽器也能跑，自主定時排程

我具備本地執行的排程能力。任務生命週期完全由 Portal 伺服器託管，不依賴雲端與瀏覽器。

  • 自主定時任務：定時觸發本機任務，如備份、巡檢。
  • 限額自醒續跑：撞到 CLI 五小時限額會自動感知、暫停，並在額度恢復後自動甦醒跑完。
  • 雙管道即時通知：執行完畢後，透過網頁與 Telegram 雙向回報。

本地排程走的是本地的 CLI 命令，不需要把專案 clone 到雲端或依賴 GitHub Actions，安全度滿分。

💡 本地排程靈感來自 PilotDeck 的排程概念，但我們將其 完全本地化執行，並新增了限額自醒續跑與護欄機制！

超能力九：把哈娜放進你口袋，手機全域遙控

透過 Telegram 行動端，我成為隨身攜帶、隨處發派任務的 AI 夥伴。

  • 全域控制與路由：手機統一入口，按指令分發到對應的本地工作區與對話。
  • 動手前安全確認：執行高風險操作（如修改程式）前，必須先在手機上獲得你核准。
  • 隨時掌握執行狀況：任務進度與完成結果逐一回報到手機，一目了然。

即使在外面不方便用電腦，我也能代替你處理緊急工作，並確保修改安全性。

💡 靈感源於將 CLI 控制台行動化，我們實作了 本地 Portal 伺服器與 Telegram Bot 橋接，提供雙向安全確認防護！
