# SPEC — 專案管理（Project Management：清單／看板／甘特圖）

> Status: 定稿 for build ｜ Owner: 老闆 + Hana ｜ 規劃日 2026-07-30
> 影響範圍：`portal/server.js`（PM API）、`portal/index.html`（專案管理面板：清單／看板／甘特圖三視圖）、`global-knowledge/pm/`（持久化，git-ignored）、`.harness/commands/pm.md`（指令技能）。
> 一句話：**指揮官規劃「任意專案」的工具**——一份結構化資料（任務＋開始/結束日＋% 完成＋前後相依），用**清單 / 看板 / 甘特圖**三種視圖看同一份資料；可在網頁手動編、也可用對話叫 Hana 幫你建/改，或用 `/pm` 指令。

---

## 1. 動機與定位（與既有機制的分界，這條最關鍵）

指揮官要一個「正常專案管理系統」該有的東西：任務清單、任務前後關係、預計完成日、以甘特圖呈現。關鍵洞見（規劃對話已釐清）：

> **清單（List）、看板（Kanban）、甘特圖（Gantt）不是三選一，而是同一份結構化資料的三種視圖。** 只要底層資料有 `start/end/deps/progress`，三種視圖都只是渲染方式。MS Project／Jira／Asana／Monday／ClickUp 都是這條路。

因此本能力做的是**一套全新、獨立的結構化資料 + 三視圖渲染**，**不改造 Dashboard、不吸收既有 TASK/worktable**。

工作區裡已經有三個「像 task 的東西」，PM 是**第四個、刻意獨立的筒倉**，設計上與它們清楚分界：

| 現有機制 | 擁有者/用途 | 有日期? | 有相依/甘特? | 與 PM 的關係 |
|---|---|---|---|---|
| Worktable `TASK.md` | **Hana 的開發路線圖**（敘事型記憶、由 Hana 執行） | ❌ | ❌ | 完全不碰 |
| 便條貼 `/note` | 指揮官**個人待辦白板**（純提醒） | ✅ 到期日 | ❌ | **完全獨立**（見決策 1） |
| 排程 Scheduler | 定時**執行** prompt | ✅ cron | ❌ | 不相干 |
| **（本 spec）專案管理** | 指揮官規劃**任意專案**的工期/相依/時間軸 | ✅ | ✅ | 新做 |

## 3. 資料模型（結構化資料＝一切的根）

單一 JSON 檔 `global-knowledge/pm/pm.json`（本機、git-ignored，比照 `notes/`、`schedules/` 同精神：檔案式、跨自癒重啟不丟）。內含兩個陣列：

```jsonc
{
  "projects": [ /* Project */ ],
  "tasks":    [ /* Task */ ]
}
```

### 3.1 Project（專案）
```jsonc
{
  id,            // proj_<ms>_<rand>
  name,          // 專案名
  description,   // 選填說明（純文字）
  color,         // 選填主題色 key（沿用調色盤，深淺模式都可讀）
  workspace,     // 工作區隔離標籤（見 §5）
  archived,      // 封存（移出清單、仍可查/還原）；預設 false
  createdAt, updatedAt
}
```

### 3.2 Task（任務）
```jsonc
{
  id,            // ptask_<ms>_<rand>
  projectId,     // 所屬專案（→ 由專案取得 workspace）
  name,
  start,         // 'YYYY-MM-DD'（當地日曆語意；里程碑時 == end）
  end,           // 'YYYY-MM-DD'（含當日；即預計完成日）
  progress,      // 0..100（% 完成）
  status,        // 'todo' | 'in_progress' | 'done'（看板欄；獨立存，非由日期推導，見 §9 D5）
  deps,          // [taskId, ...] FS 前置任務（這些完成後本任務才可開始）
  isMilestone,   // 里程碑＝工期 0 的時間點標記（Gantt 畫菱形）；預設 false
  order,         // 整數，清單/看板內的手動排序
  color,         // 選填
  baseline,      // 選填 { start, end } 基準線快照（原訂 vs 實際，見 §6.3 / §9 D6）
  createdAt, updatedAt
}
```

- **日期一律 date-only `YYYY-MM-DD` 當地日曆語意**；工期（天）＝`end − start + 1`。**計算「今天／是否延誤」用當地日曆組件**（`getFullYear/Month/Date`）比對，**不可用 `toISOString().slice(0,10)`**（UTC+8 會退一天，MEMORY 教訓）。
- `name`/`description` 一律**純文字**渲染（`textContent`／逃逸），不解析 HTML → 防注入。
- **相依只存前置 `deps`（FS）**：語意＝所有 `deps` 完成前，本任務不應開始。基本版**只視覺呈現＋標記違規（後項早於前項結束）**，**不自動重排**日期（自動排程屬進階、不做，見 §9 D3）。

## 4. API（`portal/server.js`）

所有面都經 `resolveWorkspace(req)`（讀 `X-Workspace` 標頭）做工作區隔離（§5）。寫檔採「讀→改→寫」全量覆蓋 + 同步寫（比照 `schedules.json`／`notes.json`），單人低併發、免資料庫。

| 端點 | 用途 |
|---|---|
| `GET /api/pm/projects?scope=workspace\|all&includeArchived=0\|1` | 列專案。預設 `scope=workspace`、不含封存。 |
| `POST /api/pm/projects` | 建專案。body `{name, description?, color?}`；自動標 `workspace`＝`resolveWorkspace(req)`。回整筆。 |
| `PUT /api/pm/projects/:id` | 改專案（`name/description/color/archived`）。刷新 `updatedAt`。 |
| `DELETE /api/pm/projects/:id` | **永久刪除**專案**及其所有任務**（破壞性、前端二次確認）。 |
| `GET /api/pm/projects/:id/tasks` | 列該專案任務（依 `order`）。 |
| `POST /api/pm/projects/:id/tasks` | 建任務。body `{name, start?, end?, progress?, status?, deps?, isMilestone?, color?}`；缺日期給合理預設（今日起 1 天）；`order` 自動接尾。回整筆。 |
| `PUT /api/pm/tasks/:id` | 改任務（`name/start/end/progress/status/deps/isMilestone/order/color/baseline`）。刷新 `updatedAt`。 |
| `DELETE /api/pm/tasks/:id` | 刪任務，並**清掉其他任務 `deps` 中對它的引用**（避免懸空相依）。 |
| `POST /api/pm/tasks/:id/baseline` | 把目前 `start/end` 存進 `baseline`（原訂快照）。清除＝`PUT {baseline:null}`。 |

- 任務端點的工作區隔離：**task 無自帶 workspace，經 `projectId → project.workspace` 對應**後過濾（比照排程「run 只帶 scheduleId、需經 scheduleId→workspace 對應」的鐵則）。跨工作區的 `projectId` 一律 404，不得操作。
- `deps` 寫入時驗證：只接受**同專案內**、**非自身**、**不成環**的 taskId（基本防呆；成環直接拒絕）。

## 5. 工作區隔離（沿用平台鐵則）

- 每個 **Project** 帶 `workspace`；建立時自動標記＝該請求解析出的工作區（Web：`X-Workspace` 標頭 `resolveWorkspace(req)`）。**Task 不自帶 workspace**，一律經 `projectId → project.workspace` 判定歸屬。
- 比對前一律 `path.resolve()`＋小寫正規化；`null`／未帶＝ harness home（`WORKSPACE_ROOT`）——與排程／便條貼隔離**同一套規則**（MEMORY「排程的工作區隔離」）。
- 面板**預設只顯示當前工作區**的專案；因這是**跨專案的個人規劃工具**，UI 提供「**全部工作區**」切換（`scope=all`）。
- **日後新增任何 PM 相關的讀取功能，務必照此 pattern 過濾**（避免跨工作區外洩，MEMORY 鐵則）。

## 6. 三視圖（`portal/index.html`，Hana 定案）

### 6.0 入口與面板外殼
- 側邊欄新增「📊 專案管理」入口，走既有 `showPanel(id)` 互斥機制（與排程頁同款、獨立空間，不塞進 Dashboard）。
- 版面：**左欄＝專案清單**（＋新專案、選取、`工作區：當前 ▾ / 全部` 切換、封存切換）；**主區＝選定專案的任務**，頂部**視圖切換 `清單 / 看板 / 甘特圖`**＋「＋新任務」。
- 三視圖共讀同一份 `tasks`（`GET /projects/:id/tasks`）、任何一處編輯都經 API 寫回單一真相，切視圖即時反映。

### 6.1 清單視圖（List）
- 表格：任務名、開始、結束、工期、% 完成、狀態、相依（前置任務名）。
- 就地新增/編輯（點列開編輯表單或就地欄位）：改 `name/start/end/progress/status/deps/isMilestone` → `PUT`。依 `order` 排序、可調整順序。
- 相依欄用**下拉多選**（同專案任務），呈現前置任務名。

### 6.2 看板視圖（Kanban）
- 三欄＝`待辦(todo) / 進行中(in_progress) / 完成(done)`。卡片顯示任務名、日期區間、% 完成、里程碑標記。
- 卡片可**拖曳跨欄** → 放開時 `PUT /tasks/:id {status}`；同欄內拖曳可調 `order`。
- 卡片點擊 → 開同一個任務編輯表單（與清單共用）。

### 6.3 甘特圖視圖（Gantt，SVG，本能力最核心的呈現）
- 輕量 **SVG** 手繪（不引大型函式庫）；時間軸 X 依專案任務的最早 `start`～最晚 `end` 自動決定範圍與刻度（日／週自適應）。一列一任務（依 `order`）。
- 每個元素：
  - **任務條**：`start`→`end` 的橫條，**依 `progress` 填充**（已完成比例著色）。
  - **里程碑**：`isMilestone` 畫**菱形**（工期 0 的時間點）。
  - **FS 相依箭頭**：從前置任務**結束端** → 後續任務**開始端**畫箭頭連線；後項開始早於前項結束時**視覺標紅**（違規提示、不自動改期）。
  - **今日線**：一條垂直「今天」標線（當地日期）。
  - **基準線 ghost**：若該任務有 `baseline`，在條上/下畫一條細的原訂區間 ghost（原訂 vs 實際對照）；無則不畫。
- 條/菱形點擊 → 開任務編輯表單。橫向可捲動看長專案。

### 6.4 深色模式與主題（MEMORY 教訓）
- 所有寫死底色的元件，內部文字色/線色必須跟 `.dark` 一起切換（避免某 mode 下撞色使字/線消失，如「Excel 全螢幕字看不到」那次）。甘特圖的軸線、格線、條色、今日線在深淺模式都要清楚可讀。

### 6.5 多專案同步甘特圖 + 觀測線（Phase 6 追加；決策 2026-07-31）

> 動機：指揮官同時推多個專案（可能分屬不同工作區），想在**同一畫面**上下並排看數個專案的甘特圖、對齊在**同一條時間軸**上，並用一條可拖曳的**觀測線**觀察「某個時間點各團隊分別在做什麼、進度如何」。**本階段只做視覺對齊＋觀測線（下方 D-PM6-1＝A）**；跨專案的正式相依（箭頭連線、異動連鎖標紅）延後（見 §12）。

**入口**：左欄專案清單支援**複選（checkbox）**。選 1 個＝維持現有單專案甘特；選 **≥2 個 → 切換為「多專案對齊視圖」**（上下分割 N 格、每專案一格）。

1. **共用時間軸（橫軸統一）**
   - 時間範圍＝**所有被選專案的 union**（最早 `start`～最晚 `end`，前後各墊 1 天），用**同一組** `minD / pxPerDay / xOf()` 餵給每一格 → 各格天生對齊。**把現有 `pmRenderGantt()` 內部算時間座標的那段抽成可傳入 `minD/pxPerDay` 的純函式**，單/多專案共用，不重寫一套。
   - 頂部一條**共用日期刻度尺**（沿用現有日/週自適應邏輯），下方各專案格只畫自己的任務列。
2. **捲動行為（縱各自、橫同步）**
   - 每格是自己的**垂直捲動盒**（縱軸獨立，長專案格內自捲）。
   - **橫向捲動同步**：任一格 `scrollLeft` 改變 → 用 event listener＋**防重入 flag** 同步到其他格與頂部刻度尺（避免互相觸發成迴圈）。
3. **觀測線（Observation Line）— 決策 Q2=a：date-anchored**
   - 一條**跨所有格全高**的垂直導引線，用**絕對定位的 overlay**（不塞進任何單一格的 SVG，才能橫跨）。
   - **釘在「日期」而非「畫面位置」**（date-anchored）：預設落在畫面中央對應的日期；時間軸橫捲時，它跟著那個日期移動（該時刻不變）。提供「**↩ 回到畫面中央**」快捷鈕（捲遠後拉回）。
   - **可左右拖曳**改觀測日期；**hover 觀測線即顯示該日精確日期 tooltip**（決策：日期密集時光看位置不好判讀，故 hover/拖曳都要浮出 `YYYY-MM-DD`）。
   - **讀數面板**：觀測線停在某日 → **每格即時列出「當天正在進行的任務名＋進度%」**（該日落在 `start..end` 區間內的任務），真正實現「觀測某時間點各團隊進度」。
   - 深淺模式皆清楚可讀（線色/tooltip/讀數背景跟 `.dark` 切換，MEMORY 教訓）。
   - **DOM 清理護欄**：切回單專案／關面板時，移除 overlay 與 scroll/hover/drag 的 event listener，避免殘留監聽或洩漏。

#### 6.5.1 觀測線擴及單一專案 + 顯示開關（2026-08-16 追加）

- **單一專案甘特圖也有觀測線**：語意與上面完全相同（date-anchored、可左右拖曳、hover/拖曳浮出 `YYYY-MM-DD`、讀數列出當日進行中任務與當日里程碑），只是範圍是這一個專案；overlay 疊在甘特盒（`#pm-gantt-box`，`position:relative`）上，橫捲時跟著日期走，捲到左側名稱欄底下時自動隱藏。
- **顯示／隱藏開關**：單一專案在甘特圖上方、多專案在標題列各一個 checkbox，**共用同一個偏好**（`localStorage.pm_obs_show`，預設顯示），兩視圖勾選狀態一致。關閉時連同觀測日、「回到畫面中央」與讀數一起隱藏。
- **DOM 清理護欄同上**：切離甘特分頁（`pmRenderActiveView`）與離開 PM 面板（`views/pm.js` 的 `unmount`）都要呼叫 `pmObsCleanup()`，收掉掛在 `document` 的 mousemove/mouseup。

#### 6.5.2 版面高度不可溢出（2026-08-16 修正）

多專案視圖的可用高度＝容器 `clientHeight` **扣掉**自身 `pb-4` padding、頂部刻度尺列、負荷列（含其 `mt-1`）與底部主捲軸，才拿去均分各 pane；且已拖曳過的高度在可用空間變小時**等比縮回**，`#pm-multi-panes-col` 另加 `overflow-y:auto` 當最後保險。否則 pane 會溢出去**壓在人員負荷列上（重疊）**——這是實際回報過的 bug，日後改這塊版面務必維持這三道防線。

- **開放決策 D-PM6-1（跨專案正式相依）**：本階段**只做 A（視覺對齊＋觀測線、用眼睛看互相影響）**；**B（跨專案 deps 資料模型＋面板間相依箭頭＋異動連鎖標紅）延後**，待正式上線用一段時間後再評估（Charles 2026-07-31 拍板）。→ 列 §12 後續。

### 6.6 人員篩選（2026-08-16 追加）

- **範圍**：清單／看板／甘特圖三視圖共用**同一組**人員選擇（切換視圖不重設）。**總覽不套用**（它是全專案統計），故在總覽頁隱藏此按鈕。多專案對齊視圖本次不含。
- **選單**：單一專案工具列上的「人員」下拉，checkbox 複選；固定第一項是 **未指派**，其後是啟用中的人員（已停用者若仍有任務掛著也列出，否則那些任務永遠篩不出來）；上方有 **全選／全不選**。
- **狀態表示（不變量）**：`pmState.assigneeFilter` **`null` ＝ 全部**（不篩選），陣列＝被勾選的 key（resource id 或 `__unassigned__`），`[]` ＝ 全不選。**不可**用「全部 key 的陣列」代表全選——否則之後新增的人員會被靜默濾掉。勾滿時要自動收斂回 `null`。
- **任務歸屬**：指派到已被刪除的人員的任務，視同**未指派**（與 `pmFmtAssignee` 的顯示一致）。
- **連帶效果**：甘特圖的**人員負荷列**只顯示被選到的人（`pmGanttBuildLoadRows(opts.resourceFilter)`）；**觀測線讀數**也只算篩選後的任務。相依箭頭遇到被濾掉的前置任務會自動略過（`idxById` 查不到即 return），不會畫到別處。
- **空集合**：篩選後沒有任務時顯示「目前的『人員』篩選沒有符合的任務」，與「這個專案還沒有任務」是兩種不同訊息，不可混用。
- **DOM 清理護欄**：下拉開啟時掛在 `document` 的 mousedown（點外面關閉）必須在關閉、切到總覽、以及 `views/pm.js` 的 `unmount()` 時收掉（同 `pmObsCleanup()` 慣例）。

## 14. 人力資源（Resource Management：人員、負荷、警示色）— 2026-08-15 追加

> 動機（指揮官原話）：「每個專案可以設定人員，及對應的負荷（每週投入工時或投入比例），每個任務也可以選擇人員；當我們看到甘特圖的時候，若超出該人員的負荷、或進度 delay 時要有不同的顏色表示。」

### 14.1 決策摘要（Charles 2026-08-15 拍板）

| # | 議題 | 拍板 |
|---|---|---|
| R1 | 人員名單範圍 | **工作區共用一份人力池**（不是每專案各建）。同一人常跨專案，唯有共用才算得出「這週被多個專案加起來塞爆」。 |
| R2 | 負荷單位 | **內部一律存「每週可投入工時」（小時）**；UI 可用百分比輸入，存檔前換算（例：50% × 40h 基準 = 20h）。不並存兩套單位。 |
| R3 | 任務吃掉多少工時 | 每個任務填 **`estimateHours`（預估工時）**，**平均攤到工期天數**（每日負載 = `estimateHours / 工期天數`）。未填則視為「整個工期全職投入」＝以該人員每日可投入工時計。 |
| R4 | 一任務指派幾人 | **只做單人（`assigneeId`，單值）**。指揮官明示：所有工作都會拆解到「一個人可處理」的顆粒度，需多人時就把不同人負責的項目再細拆——這才是真正的專案執行計畫管理。**不做多人指派、不做每人各自工時**。 |
| R5 | 甘特圖警示 | **兩層都做**：① 任務條本身依「延誤／落後／正常」上色；② 另加**人員負荷列**（每人一列、逐週顯示負荷率），超載上色。只做任務條看不出「是誰被塞爆」。 |

### 14.2 資料模型追加

**新增 `resources` 陣列**（與 `projects`／`tasks` 同存 `global-knowledge/pm/pm.json`）：

```jsonc
{
  id,             // res_<ms>_<rand>
  name,           // 人員名稱（純文字）
  role,           // 選填職稱/角色
  color,          // 選填代表色（甘特圖負荷列、任務條標記用）
  weeklyHours,    // 每週可投入工時（小時，預設 40）
  workspace,      // 工作區隔離標籤（規則同 Project，見 §5）
  archived,       // 離場/停用；預設 false
  createdAt, updatedAt
}
```

**`Task` 追加兩個欄位**（皆選填、舊資料相容）：

```jsonc
{
  assigneeId,     // resource id｜null＝未指派（單值，R4）
  estimateHours   // 預估工時（小時）｜null＝未估（依 R3 退回「全職投入」）
}
```

- **人力池屬工作區層級**，不掛在專案底下；專案透過任務的 `assigneeId` 使用人力池成員。
- 刪除人員時：**不連帶刪任務**，只把引用到它的任務 `assigneeId` 清為 `null`（比照刪任務清 `deps` 的既有作法）。日常應走 `archived`，非刪除。
- 跨工作區防護：`assigneeId` 寫入時驗證該 resource 與該任務所屬 project **屬同一工作區**，否則 400 拒絕。

### 14.4 負荷與延誤的判定規則（唯一定義，前後端共用語意）

**每日負載**：任務 `t` 在其 `start..end` 區間內每一天貢獻
`dailyLoad(t) = (t.estimateHours ?? assignee.weeklyHours / 5 × 工期天數) / 工期天數`
（未估工時＝視為該人整個工期全職投入；里程碑 `isMilestone` 工期 0，**不計入負荷**。）

**週負荷率**：以**週一為週起點**（本地日曆），
`ratio = Σ dailyLoad(該週內的工作日) / resource.weeklyHours`
- **只攤在「工作日」上**（2026-08-25 修正，見 §14.9）：週六日一律不算，再扣掉該人員自己的休假日；`ratio` 的分母也隨之逐週伸縮。

**負荷色階**（甘特圖負荷列）：`ratio > 1.0` → 紅（超載）；`0.8 ≤ ratio ≤ 1.0` → 黃（吃緊）；`< 0.8` → 綠/中性。

**任務延誤判定**（任務條顏色，`status !== 'done'` 才判）：
- `expected = clamp((今天 − start + 1) / 工期天數, 0, 1) × 100`（今天用**本地日曆組件**算，不可 `toISOString()`，MEMORY 教訓）
- `end < 今天` 且 `progress < 100` → **逾期（紅）**
- `progress < expected − 10` → **落後（橘）**
- 其餘 → 正常（原色）；`status === 'done'` → 完成色（不判警示）
- **超載的任務條另加標記**：其負責人在該任務任一週超載時，任務條加上斜紋/邊框標記（與延誤色可並存，兩件事不互相覆蓋）。

     - 資料一律取自 `GET /api/pm/workload`（單一真相，§14.3），前端**不重算**負荷；新增前端快取 `pmProjWorkload`（專案範圍）與既有 `pmWorkload`（全部專案）並存，兩者都在 `pmLoadTasks()` 內載入，故總覽 render 維持同步。
     - 未指派負責人、或缺起訖日期、或里程碑的任務**不計入**（沿用 §14.4 判定），表格會提示無資料。

### 14.9 工作日與個人休假日（2026-08-25 追加，取代 §14.4「只按曆日平均攤」）

> 指揮官回報：一個 3 天的開發從週五排到下週二，系統算成 40 小時（跨 5 個曆日），人員負荷立刻假性超載。根因不是缺欄位，而是**把週末當工作日**。

**決策（Charles 2026-08-25 拍板）**

| # | 議題 | 拍板 |
|---|---|---|
| W1 | 週末 | **一律非工作日**。每週固定 5 個工作天。 |
| W2 | 國定假日 | **不做全域假日表**。理由：團隊人少、每個人都可能有固定排休或調休，全公司一份反而不準。 |
| W3 | 休假日掛在哪 | **掛在「人」身上**：`Resource.daysOff`（週末以外的不上班日：排休／調休／特休／國定假日調整）。手動維護。 |
| W4 | 甘特圖呈現 | **畫出來，但不切斷任務條**。非工作日以淡色直條標示（週末一種淡度、個人休假再明顯一點），任務條照樣連續橫跨——切斷會讓拖曳、依賴線、里程碑全部變複雜，投報率不划算。直條跟著**該列任務的負責人**走（同一天對甲是休假、對乙不是）。 |

**資料模型追加**：`Resource.daysOff: ['YYYY-MM-DD', ...]`（選填，舊資料視為 `[]`）。寫入前經 `normalizeDaysOff()` 正規化（只收 `YYYY-MM-DD`、去重、排序）；`POST/PUT /api/pm/resources` 皆接受。

**計算規則（`portal/pm.js` `computeWorkload`，前後端唯一真相）**
- `isWorkday(人, 日) = 非週六日 且 不在該人 daysOff 內`
- 每日負載 = `(estimateHours ?? 每日全職工時 × 工期內工作日數) / 工期內工作日數`，**只分配在工作日上**（週末與休假日為 0）。
- **可投入工時逐週伸縮**：`capacityHours = weeklyHours / 5 × 該週工作日數`。這是「請兩天假的那一週，可投入只有 3 天份」的唯一實作點；原本固定除以 5 會高估產能。
- 回傳多一個 `workdays`（該週工作日數），供前端 hover 說明「已扣休假」。
- **保險**：整段工期都落在非工作日（例如只排了週六日）→ 退回按曆日攤，不讓工時憑空消失（靜默算成 0 比算多更危險）。

**UI**
- 人員設定新增「🌴 休假日」區塊：可加單日或一段區間（區間會自動略過週末，因為週末本來就不算）；清單以標籤呈現、可逐一移除。人力池列表顯示 🌴N 並 hover 出日期。
- 甘特圖：任務列與人員負荷列都畫非工作日直條；圖例新增「週末」「個人休假」。
- 總覽逐週表：底色的分母改用後端逐週的 `capacityHours`，hover 標註「工作日 N 天，已扣休假」。

**Excel 匯出（`portal/pm-export.js`）**
- 「清單」新增 **F 工作天**（`NETWORKDAYS(開始, 結束, 該負責人的休假日)`，全落在非工作日時退回曆日工期）；其後欄位letter位移，所有公式與條件格式已同步重算。**L 每工作日工時** = 預估工時 / 工作天。
- 新增兩張輔助頁（刻意可見，方便逐格對帳）：
  - **休假日**：一欄一人，欄內是他週末以外的休假日；靠 `INDEX/MATCH(負責人)` 被引用為 `NETWORKDAYS` 的 holidays 引數。全員都沒休假時整張表不產生，公式退化成單純 `NETWORKDAYS`。
  - **週工時明細**：一列一任務、一欄一週，格＝該任務在該週的工時。**為什麼需要它**：改成工作日後，重疊天數不再能在 `SUMPRODUCT` 內逐元素展開（`NETWORKDAYS` 不是逐元素函數），故拆成單格公式先算好，總覽再用 `SUMPRODUCT((負責人=人名)*該週欄)` 加總——整條鏈仍然全公式、改日期或改休假會自動重算。
- 總覽新增第二張表「**該週可投入工時**」（`NETWORKDAYS(週一, 週日, 該人休假日) × 每日全職工時`），逐週表的底色門檻改以它為分母。
- 甘特圖頁新增週末灰色直條（`WEEKDAY(欄日期,2)>5`）。**個人休假不在 Excel 甘特圖上色**：條件格式若跨頁籤引用「休假日」表，部分 Excel 版本會判為不合法而讓整份格式化失效，寧可少一個顏色也不冒毀檔風險。

**已知限制（刻意）**：休假日是手動維護的，忘記填就等於那天照算有在工作，系統不會提醒——不憑空猜誰放假。若日後嫌麻煩，再議「請假登記」入口。

## 15. Excel 匯出帶人力資訊（2026-08-25 追加，取代 §14.6 的「匯出不動」）

### 15.1 頁籤順序與清單欄位

> 2026-08-25 稍晚：欄位與公式再度因 §14.9（工作日／個人休假）調整，以 §14.9 的敘述為準；本節保留當時的設計脈絡。

- 頁籤順序改為 **總覽 → 清單 → 甘特圖**（總覽先 `addWorksheet` 即為第一頁籤）。
- 「清單」新增 **B 負責人**（插在任務名稱後，故其後所有欄位letter位移；公式已全數重算）、**J 預估工時(h)**、**K 每日工時(h)**。
  - `J`：任務有填 `estimateHours` → 寫常數；沒填但有負責人 → 寫公式 `工期 × (每週工時/5)`，即 §14.4 R3「未估工時＝整段工期全職投入」的公式化版本，**改日期會自動重算**。
  - `K = J / 工期`：預估工時平均攤到工期每一天（含週末），與 `computeWorkload` 同一規則，是逐週表唯一的計算基礎。
- 「甘特圖」列首改為兩欄：**A 任務、B 負責人**（皆為指向清單同列的公式），凍結窗格改 `xSplit: 2`，日期欄自 C 欄起；所有 conditional formatting 公式同步位移。

### 15.2 總覽「人員逐週投入工時」表（純公式）

- 表頭列 = 專案期間內每個週一（真實日期序號，供公式直接引用）；列 = **本專案有被指派到的人員**（人名重複時自動加序號後綴，因公式以人名比對）。
- 每格公式（純 `SUMPRODUCT`，不用陣列公式、不需 Ctrl+Shift+Enter）：
  `SUMPRODUCT((負責人=本列人名)*(里程碑<>"是")*每日工時*重疊天數*(重疊天數>0))`，
  其中重疊天數＝該任務區間與該週（週一~週日）的交集天數，以 `((結束<週日)*結束+(結束>=週日)*週日) - ((開始>週一)*開始+(開始<=週一)*週一) + 1` 逐元素展開（不用 `MAX/MIN`，因其在 `SUMPRODUCT` 內不是逐元素運算）。無日期的任務重疊天數為負 → 自動被 `(重疊天數>0)` 濾掉。
- 最右「總工時(h)」＝該列各週 `SUM`；最下「每週合計」＝各欄 `SUM`；`B` 欄放該人「每週可投入(h)」。
- 底色以 conditional formatting 標示**本專案**該週佔用比例：綠＝有排但寬裕、黃＝≥80%、紅＝超過可投入工時。（畫面上的表底色是「跨全部專案」的負荷，Excel 版只看本專案——因為匯出的是單一專案，跨專案數字不在檔案裡，寧可少講也不寫死一個不會重算的數字。）
- 總覽統計卡追加「預估總工時(h)」＝`SUM(清單!J)`；完成度長條改為公式 `REPT` 文字條（原本用 20 個 CF 儲存格畫，欄寬會跟逐週表打架）。

### 15.3 順手修掉的日期偏移

`exceljs` 把 JS `Date` 以 UTC epoch 換算成序號，在 UTC+8 會讓每個日期儲存格早 8 小時、**在 Excel 裡顯示成前一天**（既有問題）。現在日期一律以 `excelSerial()` 直接寫成本地日曆序號（數字 + 日期格式），顯示正確，且逐週表公式中的週一/週日序號常數才能與儲存格精確比對。

### 15.4 驗證

`t_pmcheck.js`（暫存腳本）以與 Excel 相同的語意逐格重算逐週表，與 `computeWorkload()`（畫面用的計算）逐格比對，含「未指派」「無日期」「里程碑」三種邊界任務——結果完全一致。
