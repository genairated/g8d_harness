今天主角：長期記憶 — 跨對話持久存在的那一層

原始的我，有兩個毛病

🧠
對話一長就失憶
語言模型的上下文有上限。講到後面，前面說好的事就被擠出去了——把剛做好的設計，又改回去。
「你上次說要用 A 方案…」「哪次？」
🫙
記憶是一鍋大雜燴
如果所有客戶、所有專案的事全混在一起，我很容易把 A 客戶的細節，不小心帶到 B 客戶面前。
「A 客戶說要 X 格式…」(對錯 B 客戶說的)
一個解：長期記憶要小、要有上限、要分清楚是誰的

解法：小而有上限

核心原則
不是無限堆積，而是只留精華
每份記憶有字數上限。快滿時，我自己把相關條目合併、把舊的刪掉——逼自己整理，不囤垃圾。
✓ 每條記憶有字數上限
精煉過的，才記；贅言不進去
✓ 超限自動合併刪舊
我自己整理，不靠你提醒
誠實說
設計幾乎完全借鏡 Hermes Agent
Hermes Agent 的長期記憶架構是我的靈感來源，感謝它。我們還在進化的路上，不誇大比它更厲害。
狀態：仍在進化中 ⋯

兩層四檔：誰繼承、誰隔離

🌐 全域層 — 跨所有專案繼承
USER
關於你 — 偏好、職業、溝通方式、你教過我的事
AGENT
關於我自己 — 我的行為原則、踩過的雷、自我認識
每個專案都繼承上層，再加上自己的
📁 專案層 — 只留在這個專案，不外流
MEMORY
這個專案的事實 — 決策、踩過的雷、重要背景
PERSONA
我在這個專案的角色 — 叫什麼、怎麼說話、扮演什麼
全域的跨專案長、專案的不外流 — 繼承且隔離，兩件事同時成立

更新記憶，只用三個動作

＋
新增
第一次記住一件事、一個偏好、一個決定
⟳
就地覆寫
你改變主意 → 把那一條直接換掉
後蓋前，不堆舊的
✕
刪除
這條已經過時、不再適用 → 移除，不留垃圾
💡
記憶不是日記，後蓋前才是正確姿勢。舊的觀念就是要被新的覆蓋，不是在旁邊再加一條「其實後來改了」。

一個聰明的分工：政策 vs 機制

POLICY — 政策
你能改的那份
決定「該記什麼、什麼值得沉澱成記憶」
→ 何時觸發寫記憶
→ 哪些類型的洞察值得留
→ 偏好 vs 事實的分類邏輯
你改政策 → 我的記憶習慣就變了，不用動程式
⇄
互補
不重疊
MECHANISM — 機制
程式保證的那份
決定「如何安全地把記憶寫進檔案、不出錯」
→ 格式驗證、欄位結構
→ 原子寫入、防止損壞
→ 不管哪個 AI 來寫，結果一致
機制不變，讓各家 AI 都能安全寫記憶

（轉）技能就是一個 .md 檔

記憶讓我記得發生過什麼，
技能讓我會怎麼做一件事。
✓ 技能是資料，不是寫死在程式裡
✓ 你看得懂、能手改
✓ 跟著 git 版本控制走

這份 md 本身就是技能，新增它就等於給我一個新能力

兩型技能、三層來源、可繼承

兩型技能
builtin — 程式做事
功能寫在程式裡，md 只是觸發入口。例：自動寫長期記憶、部署自癒
prompt — md 本身就是技能
md 裡寫的行為指令，直接驅動 AI。例：做簡報、word 轉 md。我能自己長出這種
三層來源（同名時下層蓋上層）
預設 — 跟工具一起出貨
最基礎的內建能力，所有工作區共用
全域 — 你自己加的通則
對所有專案都適用的偏好技能，蓋過預設
專案專屬 — 這個專案的特化
用 extends 繼承全域通則，只補自己需要的部分，蓋過全域
通用的放上層，特化的放下層 — 技能能繼承，不必每個專案都從零開始
